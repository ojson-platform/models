# disable-cache

Сценарии этой задачи:

- Новый вложенный запрос рождается выключенным
- Уже созданный вложенный запрос остаётся включённым
- Выключение вложенного запроса не выключает родителя
- Другое дерево не выключено
- Обращение не трогает хранилище
- Попадание не запускает фоновое обновление
- Негодный срок не отклоняет выключенный запрос
- Model выключает кэш до записи
- Обновление не кэширует снова без фабрики вызывающего

Якорь в `openspec/specs/disable-cache/spec.md` и `design.md`, раздел Technical prerequisites.

## Сделать

Зарегистрировать все девять сценариев spec id `disable-cache` через `spec`, `requirement`, `scenario`. Заголовки — из `openspec/specs/disable-cache/spec.md`. Обёртка и перенос тел — по третьему пункту Technical prerequisites в `design.md`.

Редактировать только: `src/with-cache/cache-strategy.spec.ts`, `src/with-cache/with-cache.spec.ts`. Другие spec id, зависимости, vitest не менять.

## Доказательство

Наблюдение: распространение `disableCache` по дереву контекстов, отсутствие чтения/записи и фонового обновления при выключенном кэше, поведение при невалидном TTL, выключение из Model до записи, сценарий «Обновление не кэширует снова без фабрики вызывающего».

Команды: `pnpm run test:units:fast`, `pnpm run test:types`.
