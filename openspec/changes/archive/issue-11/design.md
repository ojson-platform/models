# Прерывание запуска

Один процессный владелец прерывания внутри жизненного цикла запроса. Он владеет `kill`, `isAlive`, гонкой между завершением и прерыванием и правилом, что прерванный запуск не сохраняется. Это не базовый класс и не новый шаг `compose`.

`withDeadline` остаётся шагом композиции и последним в `compose`. Положительный срок вызывает тот же `kill`. `withDeadline(0)` по-прежнему возвращает контекст без таймера.

Вызывающий по-прежнему ловит `InterruptedError`. Приватное значение прерывания не лежит в реестре запроса и не уходит в телеметрию. Отдельной тестовой поверхности для него нет.

Имя запуска — идентичность Model из #10. Эта перемена её не задаёт заново.

Значение, уже принятое до `kill`, остаётся в мемоизации, как в baseline. Нулевой срок сам запуск не прерывает.

## Verification boundary

### interrupted-run

Сценарий дельты доказан тестом, в имени которого есть заголовок сценария.

Наблюдение снаружи владельца, через `kill`, `isAlive` и `InterruptedError`:

- «Model прерывает запуск и возвращает значение»: вызывающий получает `InterruptedError`, `isAlive()` ложно. Повтор тоже `InterruptedError`, Model не выполняется. Хранилище кэша не получает `set`. Span не получает событие `result`.
- «Истечение срока — то же прерывание»: положительный срок, Model не вернула значение до него. Ответ тот же, что у прерывания до выполнения Model: `InterruptedError`, запуск не живой, повтор Model не выполняет, `set` кэша нет, события `result` нет.
- «Прерванный запуск не оставляет успешный span»: прерывание до обращения, между шагами или по положительному сроку, и Model просит записать результат. Вызывающий получает `InterruptedError`. Span не получает событие `result` и не является записью успешного завершения.

Тест не читает приватное значение прерывания и не требует нового события ошибки. `sign` и `modelIdentity` этим тестом не вызываются.

Команды: `pnpm run test:units:fast`, `pnpm run test:types`.

## Technical prerequisites

- Depends: #10. Мемоизация и межзапросный кэш называют запуск через `modelIdentity`. Этот PR функцию, текст ключа и props не меняет.
- Код в этом PR. Владелец живёт в жизненном цикле `withModels`: `kill` и `isAlive` на контексте. Вложенный запуск делит владельца родителя. `kill` не отдаёт результат Model. Корень пакета не получает новый экспорт. Флага нет: правило действует сразу, после merge переключать нечего.
- Код в этом PR. `request` принимает результат только пока `isAlive()` в момент приёма. Иначе бросает `InterruptedError` и не оставляет мемоизированный успех. Повтор не выполняет Model. Значение, принятое до `kill`, остаётся.
- Код в этом PR. `withDeadline`: срок `<= 0` возвращает контекст как есть. Положительный срок вызывает тот же `kill`. Гонка `resolve` не подставляет возврат `kill` как результат Model. `withDeadline` остаётся последним в `compose`.
- Код в этом PR. `Cache.update`, `CacheFirst` и `StaleWhileRevalidate` спрашивают владельца перед `set`, а не только `shouldCache`. Обращение вызывающего при прерывании по-прежнему заканчивается `InterruptedError` и без записи. Фоновое обновление уже прерванного запуска заканчивается без ошибки и без новой записи. Остальное поведение кэша не меняется.
- Код в этом PR. Телеметрия спрашивает владельца перед событием `result`. Прерванный запуск события `result` не получает и не записывается как успешное завершение. Прочая телеметрия не меняется.

`withOverrides` и валидация это правило не исполняют.
