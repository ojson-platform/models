# request-identity

Сценарии этой задачи:

- Один ответ содержит прежний ключ и props
- Пропуск свойства и undefined — один ответ
- Вложенный undefined не входит в ответ
- null, false, ноль и пустая строка остаются в ответе
- Обращение и предустановка без имени отвергаются
- Без props мемоизация передаёт пустой объект
- Предустановка без props находится таким же обращением

Якорь в `design.md`, раздел Technical prerequisites: функция в `src/utils` и пункт, что `request` и `set` берут ключ и props только из её ответа.

## Сделать

Функция `modelIdentity` в `src/utils/index.ts`, рядом с `sign` и `cleanUndefined`. Из `src/index.ts` она не экспортируется. Вход — Model и props. Ответ — одно значение с ключом и props, либо отказ.

- Нет `displayName` или он пустой: `TypeError` с текстом `Model should define static displayName property`. Ключа нет.
- Props не переданы: пустой объект. У Model с именем `M` ключ `M;`, вызывающий получает пустой объект.
- В props ответа нет свойств со значением `undefined`, в том числе внутри вложенного объекта. Пропуск свойства и то же свойство со значением `undefined` дают один ответ. `null`, `false`, `0` и пустая строка остаются.
- Ключ — `displayName`, затем `;`, затем `sign` от props ответа. Порядок свойств ключ не меняет. Кодирование `sign` не заменяется.

`ctx.request` и `ctx.set` берут ключ и props только из этого ответа. Model выполняется с props ответа. Реестр запроса остаётся своим и не делится с другим запросом.

Существующее ожидание текста ошибки в `src/with-models/with-models.spec.ts` приводится к тексту из `design.md` в том же коммите.

`src/with-cache` в этой задаче не меняется. Для сценариев «Один ответ содержит прежний ключ и props» и «Пропуск свойства и undefined — один ответ» межзапросный кэш наблюдается как есть: у именованной Model с согласованными props он уже хранит тот же текст ключа.

Флага нет. `withOverrides`, телеметрия, дедлайн и валидация ключ не строят и в этой задаче не меняются.

## Доказательство

Имя каждого теста содержит заголовок своего сценария. Наблюдение — граница `model-identity` в `design.md`:

- ответ `modelIdentity`: ключ и props одним значением, импорт из `src/utils`, не из корня пакета;
- мемоизация и предустановка: `ctx.request` и `ctx.set` — сколько раз выполняется Model, какие props она получает, находится ли записанное значение;
- для двух сценариев, где назван и кэш: аргументы `get` и `set` хранилища.

`sign` тестом не вызывается. Команды: `pnpm run test:units:fast`, `pnpm run test:types`.
