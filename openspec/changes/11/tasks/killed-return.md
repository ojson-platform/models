# killed-return

Сценарии этой задачи:

- Model прерывает запуск и возвращает значение

Якорь в `design.md`, раздел Technical prerequisites: владелец в жизненном цикле `withModels`, приём результата в `request`, затем `Cache.update`, `CacheFirst` и `StaleWhileRevalidate`.

Depends: #10. Мемоизация и межзапросный кэш называют запуск через `modelIdentity`. Функцию, текст ключа и props этот PR не меняет.

## Сделать

Один владелец внутри жизненного цикла `withModels`: `kill` и `isAlive` на контексте. Вложенный запуск делит владельца родителя. `kill` не отдаёт результат Model. Приватное значение прерывания не лежит в реестре запроса. Корень пакета не получает новый экспорт. Флага нет: правило действует сразу.

`request` принимает результат только пока `isAlive()` в момент приёма. Иначе бросает `InterruptedError` и не оставляет мемоизированный успех. Повтор не выполняет Model. Значение, принятое до `kill`, остаётся в мемоизации.

`Cache.update`, `CacheFirst` и `StaleWhileRevalidate` спрашивают владельца перед `set`, а не только `shouldCache`. Обращение вызывающего при прерывании заканчивается `InterruptedError` и без записи. Фоновое обновление уже прерванного запуска заканчивается без ошибки и без новой записи. Остальное поведение кэша не меняется.

Срок и событие `result` уже спрашивают этого владельца с предыдущей задачи. Здесь они не переписываются. `withOverrides` и валидация не меняются.

## Доказательство

Имя теста содержит заголовок сценария. Наблюдение — граница `interrupted-run` в `design.md`:

- «Model прерывает запуск и возвращает значение»: вызывающий получает `InterruptedError`, `isAlive()` ложно. Повтор тоже `InterruptedError`, Model не выполняется. Хранилище кэша не получает `set`. Span не получает событие `result`.

Тест не читает приватное значение прерывания и не требует нового события ошибки. `sign` и `modelIdentity` этим тестом не вызываются.

Команды: `pnpm run test:units:fast`, `pnpm run test:types`. Уже зелёные тесты предыдущей задачи остаются зелёными.
