# model-identity

## Purpose

Идентичность вызова Model — её имя и props. Мемоизация запроса, предустановленное значение и межзапросный кэш получают ключ и props одним ответом.

## Requirements

### Requirement: Именованная Model и объект props дают один текст

У именованной Model, когда props — объект, мемоизация запроса, предустановка и межзапросный кэш SHALL использовать один и тот же текст. Текст начинается с имени, затем `;`, затем запись props. Порядок свойств запись не меняет. Без свойств объекта запись пустая: у Model с именем `M` текст `M;`. Одно свойство `a` со значением `1` даёт `M;a=1`. Свойство `a` со значением `1` и вложенный объект `nested` со свойством `b` со значением `2` дают `M;a=1&nested=b%3D2`.

#### Scenario: Повтор в одном запросе не выполняет Model

- **WHEN** в одном запросе именованную Model вызывают дважды с одним и тем же объектом props
- **THEN** Model выполняется один раз, и оба обращения получают тот же результат

#### Scenario: Порядок свойств не различает вызов

- **WHEN** два обращения к одной Model отличаются только порядком свойств объекта
- **THEN** текст идентичности совпадает, и внутри одного запроса Model выполняется один раз

#### Scenario: Другое имя или другие props — другая идентичность

- **WHEN** имя Model другое или значения props другие
- **THEN** Model выполняется отдельно, а межзапросный кэш не отдаёт запись первого вызова

#### Scenario: Кэш хранит вызов под этим текстом

- **WHEN** именованная Model с именем `M` и свойством `a` равным `1` выполняется через межзапросный кэш
- **THEN** кэш записывает результат под текстом `M;a=1`
- **AND** повтор с тем же именем и теми же props в другом запросе получает этот результат, и Model не выполняется снова

### Requirement: Пропущенное свойство объекта и undefined — та же идентичность

Свойство объекта, которого нет, и то же свойство со значением `undefined` SHALL давать один текст, в том числе внутри вложенного объекта. Model при выполнении получает объект без таких свойств. `null`, `false`, `0` и пустая строка в объекте остаются и отличают вызов от пропуска свойства.

#### Scenario: Необязательное свойство undefined совпадает с пропуском

- **WHEN** одно обращение передаёт свойство объекта равным `undefined`, а другое в том же запросе это свойство не передаёт
- **THEN** Model выполняется один раз и получает объект без этого свойства

#### Scenario: Вложенный undefined не доходит до Model

- **WHEN** во вложенном объекте свойство равно `undefined`, а повтор в том же запросе это свойство не передаёт
- **THEN** Model выполняется один раз и получает вложенный объект без этого свойства

#### Scenario: Предустановка с undefined находится обращением без свойства

- **WHEN** значение записано для именованной Model со свойством `undefined`, а затем в том же запросе к ней обращаются без этого свойства
- **THEN** обращение возвращает записанное значение, и Model не выполняется

#### Scenario: Кэш соединяет пропуск свойства и undefined

- **WHEN** в одном запросе свойство объекта передано как `undefined`, а в другом запросе то же свойство пропущено
- **THEN** межзапросный кэш отдаёт сохранённый результат, и Model выполняется один раз

#### Scenario: null, false, ноль и пустая строка отличают вызов

- **WHEN** свойство равно `null`, `false`, `0` или пустой строке, а другое обращение это свойство не передаёт
- **THEN** Model выполняется для каждого обращения

### Requirement: Model без имени

Model без имени и с пустым именем SHALL не получать идентичность. Мемоизация, предустановка и межзапросный кэш отвергают такое обращение и не выполняют Model. Кэш не читает и не записывает запись.

#### Scenario: Обращение и предустановка без имени отвергаются

- **WHEN** вызывающий обращается к Model без имени или записывает для неё значение
- **THEN** действие завершается ошибкой, и Model не выполняется

#### Scenario: Кэш не даёт идентичность Model без имени

- **WHEN** межзапросный кэш ищет Model, у которой нет имени, и props переданы
- **THEN** обращение завершается ошибкой, Model не выполняется, и кэш не обращается к хранилищу

#### Scenario: Пустое имя не получает идентичность

- **WHEN** вызывающий обращается к Model с пустым именем, записывает для неё значение или ищет её через межзапросный кэш, и props переданы
- **THEN** каждое действие завершается ошибкой, Model не выполняется, и кэш не обращается к хранилищу

### Requirement: Обращение без props

Мемоизация, предустановка и межзапросный кэш SHALL считать обращение к именованной Model без props тем же, что обращение с пустым объектом. Ключ совпадает с ключом пустого объекта. Model получает пустой объект.

#### Scenario: Без props мемоизация передаёт пустой объект

- **WHEN** в запросе без межзапросного кэша вызывают именованную Model, не передавая props, и затем повторяют это обращение
- **THEN** первый раз Model получает пустой объект, второй раз Model не выполняется

#### Scenario: Предустановка без props находится таким же обращением

- **WHEN** значение записано для именованной Model без props, а затем к ней обращаются без props
- **THEN** обращение возвращает записанное значение, и Model не выполняется

#### Scenario: Кэш без props берёт ключ пустого объекта

- **WHEN** межзапросный кэш выполняет именованную Model с именем `M`, не передавая props
- **THEN** Model получает пустой объект, и кэш записывает результат под ключом `M;`
- **AND** повтор в другом запросе с пустым объектом получает этот результат, и Model не выполняется снова

### Requirement: Один ответ даёт ключ Model и её props

Вызывающий SHALL узнавать ключ именованной Model и её props одним ответом. Мемоизация запроса, предустановленное значение и межзапросный кэш пользуются этим ответом.

В props ответа нет свойств со значением `undefined`, в том числе внутри вложенного объекта. Пропущенное свойство и то же свойство со значением `undefined` дают один ответ. `null`, `false`, `0` и пустая строка остаются и отличают ответ от пропуска свойства.

Пока мемоизация, предустановка и кэш уже дают один и тот же текст ключа, текст ответа остаётся прежним: имя, затем `;`, затем запись props. Без свойств объекта запись пустая: у Model с именем `M` текст `M;`. Свойство `a` со значением `1` даёт `M;a=1`. Свойство `a` со значением `1` и вложенный объект `nested` со свойством `b` со значением `2` дают `M;a=1&nested=b%3D2`.

#### Scenario: Один ответ содержит прежний ключ и props

- **WHEN** вызывающий спрашивает идентичность именованной Model `M` со свойством `a` равным `1`
- **THEN** ответ один: ключ `M;a=1` и props, в которых `a` равно `1`
- **AND** мемоизация запроса, предустановка и межзапросный кэш для этого обращения пользуются этим ключом и этими props

#### Scenario: Пропуск свойства и undefined — один ответ

- **WHEN** один ответ построен для именованной Model со свойством равным `undefined`, а другой — для той же Model без этого свойства
- **THEN** ключи совпадают, и ни в одних props этого свойства нет
- **AND** мемоизация, предустановка и кэш считают эти обращения одной идентичностью

#### Scenario: Вложенный undefined не входит в ответ

- **WHEN** вызывающий спрашивает идентичность именованной Model `M` со свойством `a` равным `1` и вложенным объектом `nested`, где `b` равно `undefined`, а `c` равно `2`
- **THEN** ключ равен `M;a=1&nested=c%3D2`, в props нет `b`, а `nested` содержит `c` равное `2`
- **AND** Model при выполнении получает эти props

#### Scenario: null, false, ноль и пустая строка остаются в ответе

- **WHEN** вызывающий спрашивает идентичность Model, у которой свойство равно `null`, `false`, `0` или пустой строке
- **THEN** это свойство есть в props ответа с тем же значением
- **AND** ответ отличается от идентичности той же Model без этого свойства
