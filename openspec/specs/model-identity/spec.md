# model-identity

Идентичность вызова Model сегодня — её имя и props. Мемоизация запроса, предустановленное значение и межзапросный кэш собирают эту идентичность каждая у себя.

## Requirements

### Requirement: Именованная Model и объект props дают один текст

У именованной Model, когда props — объект, мемоизация запроса, предустановка и межзапросный кэш используют один и тот же текст. Текст начинается с имени, затем `;`, затем запись props. Порядок свойств запись не меняет. Без свойств объекта запись пустая: у Model с именем `M` текст `M;`. Одно свойство `a` со значением `1` даёт `M;a=1`. Свойство `a` со значением `1` и вложенный объект `nested` со свойством `b` со значением `2` дают `M;a=1&nested=b%3D2`.

#### Scenario: Повтор в одном запросе не выполняет Model

- **WHEN** в одном запросе именованную Model вызывают дважды с одним и тем же объектом props
- **THEN** Model выполняется один раз, и оба обращения получают тот же результат

#### Scenario: Порядок свойств не различает вызов

- **WHEN** два обращения к одной Model отличаются только порядком свойств объекта
- **THEN** текст идентичности совпадает, и внутри одного запроса Model выполняется один раз

#### Scenario: Другое имя или другие props — другая идентичность

- **WHEN** имя Model другое или значения props другие
- **THEN** Model выполняется отдельно, а межзапросный кэш не отдаёт запись первого вызова

#### Scenario: Кэш хранит вызов под этим текстом

- **WHEN** именованная Model с именем `M` и свойством `a` равным `1` выполняется через межзапросный кэш
- **THEN** кэш записывает результат под текстом `M;a=1`
- **AND** повтор с тем же именем и теми же props в другом запросе получает этот результат, и Model не выполняется снова

### Requirement: Пропущенное свойство объекта и undefined — та же идентичность

Свойство объекта, которого нет, и то же свойство со значением `undefined` дают один текст, в том числе внутри вложенного объекта. Model при выполнении получает объект без таких свойств. `null`, `false`, `0` и пустая строка в объекте остаются и отличают вызов от пропуска свойства.

#### Scenario: Необязательное свойство undefined совпадает с пропуском

- **WHEN** одно обращение передаёт свойство объекта равным `undefined`, а другое в том же запросе это свойство не передаёт
- **THEN** Model выполняется один раз и получает объект без этого свойства

#### Scenario: Вложенный undefined не доходит до Model

- **WHEN** во вложенном объекте свойство равно `undefined`, а повтор в том же запросе это свойство не передаёт
- **THEN** Model выполняется один раз и получает вложенный объект без этого свойства

#### Scenario: Предустановка с undefined находится обращением без свойства

- **WHEN** значение записано для именованной Model со свойством `undefined`, а затем в том же запросе к ней обращаются без этого свойства
- **THEN** обращение возвращает записанное значение, и Model не выполняется

#### Scenario: Кэш соединяет пропуск свойства и undefined

- **WHEN** в одном запросе свойство объекта передано как `undefined`, а в другом запросе то же свойство пропущено
- **THEN** межзапросный кэш отдаёт сохранённый результат, и Model выполняется один раз

#### Scenario: null, false, ноль и пустая строка отличают вызов

- **WHEN** свойство равно `null`, `false`, `0` или пустой строке, а другое обращение это свойство не передаёт
- **THEN** Model выполняется для каждого обращения

### Requirement: Model без имени

Мемоизация и предустановка отвергают Model без имени и с пустым именем и не выполняют её.

Межзапросный кэш собирает текст и для такой Model: нет имени — текст начинается с `undefined;`, пустое имя — текст начинается с `;`.

#### Scenario: Обращение и предустановка без имени отвергаются

- **WHEN** вызывающий обращается к Model без имени или записывает для неё значение
- **THEN** действие завершается ошибкой, и Model не выполняется

#### Scenario: Кэш ищет Model без имени

- **WHEN** межзапросный кэш ищет Model, у которой нет имени, и props переданы
- **THEN** он обращается к хранилищу по тексту, который начинается с `undefined;` и содержит запись этих props

#### Scenario: Пустое имя даёт текст без имени перед разделителем

- **WHEN** межзапросный кэш ищет Model с пустым именем и переданными props
- **THEN** он обращается к хранилищу по тексту, который начинается с `;`

### Requirement: Обращение без props

Мемоизация и предустановка считают обращение без props тем же, что обращение с пустым объектом: Model получает пустой объект.

Когда межзапросный кэш собирает идентичность, а props не переданы, обращение завершается ошибкой и текста идентичности нет.

#### Scenario: Без props мемоизация передаёт пустой объект

- **WHEN** в запросе без межзапросного кэша вызывают именованную Model, не передавая props, и затем повторяют это обращение
- **THEN** первый раз Model получает пустой объект, второй раз Model не выполняется

#### Scenario: Предустановка без props находится таким же обращением

- **WHEN** значение записано для именованной Model без props, а затем к ней обращаются без props
- **THEN** обращение возвращает записанное значение, и Model не выполняется

#### Scenario: Кэш без props завершается ошибкой

- **WHEN** межзапросный кэш собирает идентичность именованной Model, а props не переданы
- **THEN** обращение завершается ошибкой, и Model не выполняется
