# stale-while-revalidate

Стратегия stale-while-revalidate при промахе выполняет Model и сохраняет результат. При попадании, пока кэш запроса включён, сразу возвращает сохранённое значение и обновляет его в фоне.

## Requirements

### Requirement: Промах выполняет Model и сохраняет результат

Если записи нет, Model выполняется один раз. Вызывающий получает её результат, не дожидаясь записи. Если кэш запроса к этому моменту включён, результат записывается. Ошибка записи до вызывающего не доходит. Если Model завершается ошибкой, ошибка доходит до вызывающего, и запись не создаётся. Фоновое обновление при промахе не запускается.

#### Scenario: Первое обращение сохраняет результат

- **WHEN** записи нет, и вызывающий обращается со стратегией stale-while-revalidate
- **THEN** Model выполняется один раз, вызывающий получает её результат, и хранилище получает этот результат

#### Scenario: Ошибка Model не сохраняется

- **WHEN** Model при промахе завершается ошибкой
- **THEN** вызывающий получает эту ошибку, и хранилище не получает запись

### Requirement: Попадание сразу возвращает сохранённое и обновляет его в фоне

Пока кэш запроса включён, обращение возвращает сохранённое значение, не дожидаясь обновления. Обновление идёт отдельно: Model выполняется снова, и новое значение записывается в хранилище. Ответ этого обращения остаётся прежним. Следующее обращение получает уже новое значение, если запись удалась.

Если обновление завершается ошибкой, запись не меняется. Вызывающий уже получил прежнее значение, и следующее обращение тоже получает его.

Пока обновление тех же Model и props ещё идёт, следующее такое обновление не выполняет Model ещё раз. Когда обновление закончилось, следующее попадание снова запускает обновление.

#### Scenario: Ответ не ждёт фонового обновления

- **WHEN** значение уже сохранено, и другой запрос обращается со стратегией stale-while-revalidate
- **THEN** вызывающий сразу получает сохранённое значение
- **AND** Model выполняется ещё раз, и хранилище получает новое значение

#### Scenario: Сбой обновления оставляет прежнее значение

- **WHEN** фоновое обновление завершается ошибкой
- **THEN** обращение, которое его запустило, уже вернуло прежнее значение, и следующее обращение тоже получает прежнее значение

#### Scenario: Параллельные обновления одной записи выполняют Model один раз

- **WHEN** два фоновых обновления одних и тех же Model и props начинаются, пока первое ещё не закончилось
- **THEN** Model выполняется один раз, и хранилище получает одну новую запись
